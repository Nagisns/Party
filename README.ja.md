# Party

[English](README.md) | [日本語](README.ja.md)

Python と `discord.py` で作られた Discord Bot です。
スラッシュコマンドと日本語表示に対応しています。

現在のリリースは **0.3.0** です。このプロジェクトはプレリリースとして開発中です。
リリース履歴は [変更履歴](CHANGELOG.md) を参照してください。

## 主な機能

- **コマンドガイド:** 前後のページへ移動するボタンを使い、4 ページの埋め込みメッセージで
  コマンドの詳細を確認できます。
- **ヘルプ:** 利用可能なスラッシュコマンドを、埋め込みメッセージ（Embed）で一覧表示します。
- **Ping:** Bot の WebSocket の遅延をミリ秒単位で表示します。
- **サイコロ:** 2〜1000 面のサイコロを振り、結果を埋め込みメッセージで表示します。
- **歓迎メッセージ:** Bot がサーバーに参加したとき、システムチャンネルが設定され、
  Bot に送信権限があれば、そのチャンネルへ歓迎の埋め込みメッセージを送ります。
  タイトルと説明文は、サーバーの優先言語が日本語なら日本語、それ以外なら英語になります。
- **日本語表示:** ユーザーの Discord の言語設定が日本語の場合、
  コマンドや引数の説明、応答を日本語で表示します。
- **エラーメッセージ:** スラッシュコマンド共通のエラーハンドラーが、
  言語設定に応じたエラーを、コマンドを実行したユーザーにだけ表示します。
- **拡張機能の自動読み込み:** 起動時にコマンドとイベントの拡張機能を検出し、読み込みます。

## コマンド

| コマンド | 説明 |
| --- | --- |
| `/commands` | ボタンでページを切り替えられるコマンドガイドを表示します。 |
| `/help` | 登録済みのスラッシュコマンドとその説明を、埋め込みメッセージで一覧表示します。 |
| `/ping` | Bot の WebSocket の遅延をミリ秒単位で表示します。 |
| `/roll` | 指定した面数のサイコロを 1 回振り、結果を埋め込みメッセージで表示します。 |

4 つのコマンドはいずれも、Discord のスラッシュコマンドの候補から選択できます。
`/commands`、`/help`、`/ping` に引数はありません。
`/roll` には、サイコロの面数を指定する必須の引数 `maximum` があり、
**2〜1000** の整数を指定します。結果は **1 以上 `maximum` 以下** の整数になります。

たとえば、6 面のサイコロを振る場合は次のように入力します。

```text
/roll maximum:6
```

`/commands` のガイドは、目次、`/help`、`/ping`、`/roll` の詳細の順に並んでいます。
左右の矢印ボタンでページを切り替えられ、最初のページから前へ進むと最後のページに、
最後のページから次へ進むと最初のページに戻ります。
ページを切り替えると、チャンネル内の同じメッセージが更新されます。
そのメッセージを閲覧できるユーザーなら、誰でもボタンを操作できます。

ボタンは 180 秒間操作しないとタイムアウトします。続けて使う場合は `/commands` を再実行してください。
`/commands` は、ユーザーごとに 5 秒間に 1 回まで実行できます。

## 必要なもの

- Python 3.15 以降（`pyproject.toml` で指定）
- Discord Bot のアプリケーションと、その Bot トークン
- Bot を追加できる Discord サーバー
- `discord.py` 2.7.1 以降
- `python-dotenv` 1.2.4 以降

## セットアップ

### 1. プロジェクトを取得する

このリポジトリをクローンまたはダウンロードし、
プロジェクトのディレクトリでターミナルを開いてください。

### 2. 依存パッケージをインストールする

```bash
python -m pip install "discord.py>=2.7.1" "python-dotenv>=1.2.4"
```

上記のバージョン要件は `pyproject.toml` と一致しています。
`uv.lock` に記録されたバージョンをインストールする場合は、uv を使います。

```bash
uv sync --locked --no-dev
```

### 3. Discord Bot を作成・設定する

1. [Discord Developer Portal](https://discord.com/developers/applications) を開きます。
2. アプリケーションを作成し、**Bot** の設定を開きます。
3. Bot トークンを生成またはリセットし、次の手順で使うためにコピーします。
4. [Discord のアプリ設定ガイド](https://docs.discord.com/developers/quick-start/getting-started) に従い、
   `bot` と `applications.commands` のスコープを使って、サーバーへのインストールを設定します。
5. [サーバーへのインストール](https://docs.discord.com/developers/resources/application#installation-context) に必要な
   **サーバー管理（Manage Server）** 権限を持つアカウントで Bot を招待します。
   サーバーのテキストチャンネルでコマンドを使うメンバーには、
   **チャンネルを見る（View Channels）**、**メッセージを送信（Send Messages）**、
   **アプリコマンドを使う（Use Application Commands）** の権限が必要です。
   チャンネルごとの権限設定や
   [アプリケーションコマンドの権限](https://docs.discord.com/developers/interactions/application-commands#permissions) により、
   利用が制限される場合もあります。
   [コマンド実行時の権限に関する Discord チームの説明](https://github.com/discord/discord-api-docs/discussions/5097) も参照してください。

現在のスラッシュコマンドについては、インストール時に Bot ロールの追加権限を
要求する必要はありません（`permissions=0`）。テキストや埋め込みメッセージの応答には
[インタラクションへの応答](https://docs.discord.com/developers/interactions/receiving-and-responding#responding-to-an-interaction) を使い、
通常のチャンネルへのメッセージ送信とは異なる権限ルールが適用されます。
[インタラクションと Webhook の権限に関する Discord の説明](https://docs.discord.com/developers/change-log#changes-to-bot-permissions-for-interactions-and-webhooks) を参照してください。
Bot に **管理者（Administrator）** 権限を付ける必要はありません。

歓迎メッセージを受け取るには、サーバー設定でシステムチャンネルを指定し、
そのチャンネルで Bot に **チャンネルを見る（View Channel）**、
**メッセージを送信（Send Messages）**、**埋め込みリンク（Embed Links）** の権限を許可してください。
歓迎メッセージは通常のチャンネルメッセージとして送信するため、
[チャンネルへのメッセージ送信の権限](https://docs.discord.com/developers/resources/message#create-message) が適用されます。
Bot のロールとチャンネルごとの権限設定の両方を確認してください。
システムチャンネルが未設定の場合、歓迎メッセージは送信しません。
権限エラーは警告として、それ以外の HTTP エラーはトレースバック付きでログに記録します。

Bot はデフォルトの Gateway インテントを使います。
現在のスラッシュコマンドには **Message Content Intent**、**Server Members Intent**、
**Presence Intent** は不要で、これら 3 つの特権インテントは無効のままで利用できます。
詳しくは [discord.py のインテントガイド](https://discordpy.readthedocs.io/en/stable/intents.html#message-content) を参照してください。

### 4. 環境変数を設定する

プロジェクトのディレクトリに `.env` というファイルを作成します。

```env
TOKEN=your_bot_token_here
```

`your_bot_token_here` を自分の Bot トークンに置き換えてください。
トークンは公開せず、`.env` を Git にコミットしないでください。
このプロジェクトの `.gitignore` では、すでに `.env` を除外しています。

`TOKEN` を環境変数として直接設定することもできます。
[python-dotenv のドキュメント](https://github.com/theskumar/python-dotenv#readme) にあるとおり、
既存の環境変数は `.env` から読み込む値より優先されます。

`TOKEN` が未設定、空文字列、または空白文字だけの場合、
Bot はエラーメッセージを表示し、終了コード `1` で終了します。

### 5. Bot を起動する

プロジェクトのディレクトリで、次のコマンドを実行します。

```bash
python src/bot.py
```

uv で依存パッケージをインストールした場合は、プロジェクトの仮想環境で起動します。

```bash
uv run --locked --no-dev python src/bot.py
```

起動時には、`src/cogs/` からコマンドの拡張機能を、`src/events/` からイベントの拡張機能を
検出して読み込み、日本語の翻訳機能を登録し、グローバルなスラッシュコマンドを同期します。
コンソールには、登録済みの Cog イベントリスナーの総数、同期したコマンド数、
ログインした Bot が表示されます。同じイベントに複数のリスナーが登録されている場合も、
それぞれを個別に数えます。

起動したら、サーバーで `/commands`、`/help`、`/ping`、`/roll maximum:6` を試してください。
プレフィックスコマンドの `!help` は無効です。
コマンド一覧には `/help`、各コマンドの詳細には `/commands` を使ってください。

## コマンドの追加

コマンドは `src/cogs/` 内の Cog 拡張機能として管理しています。
起動時に `cogs` の直下にあるモジュールとパッケージを検出し、名前のアルファベット順で読み込みます。
名前が `_` で始まるものは除外するため、拡張機能として読み込ませたくないヘルパーモジュールには
この接頭辞を付けてください。

コマンドを追加するには、`src/cogs/example.py` などのモジュールを作成し、
Cog とコマンドを定義します。さらに、`await bot.add_cog(...)` を呼び出す
`async def setup(bot)` をエントリーポイントとして用意してください。
Bot を再起動すると、新しい拡張機能を検出してコマンドを同期します。
`src/mybot.py` を変更する必要はありません。

検出される拡張機能には、すべて `setup` エントリーポイントが必要です。
拡張機能の読み込みに失敗した場合、コマンドを同期する前に起動処理が停止します。

## イベントリスナーの追加

イベントリスナーは `src/events/` 内の Cog 拡張機能として管理しています。
各リスナーに `commands.Cog.listener()` を付け、`await bot.add_cog(...)` で Cog を登録する
`async def setup(bot)` エントリーポイントを用意してください。
Cog 名には重複しない名前を使ってください。また、`bot.py` からイベント処理を移す場合は、
両方の処理が実行されないよう、元のハンドラーを削除してください。

起動時には、コマンドの拡張機能、イベントの拡張機能の順に読み込みます。
各ディレクトリ直下のモジュールとパッケージは名前のアルファベット順で読み込み、
名前が `_` で始まるものは除外します。
新しいイベントの拡張機能を検出するには Bot を再起動してください。
`src/mybot.py` の変更は不要です。イベントリスナーは Cog の追加時に登録されるため、
`tree.sync()` は必要ありません。

## テスト

このプレリリースには自動テストスイートが含まれていません。
セットアップ後は、次の手順で手動確認してください。

1. Bot を起動し、コンソールに `Registered 2 event listeners.` と `Synced 4 commands.` が表示され、
   その後ログインが成功することを確認します。
2. `/help` を実行し、埋め込みメッセージに `/commands`、`/help`、`/ping`、`/roll` と各説明が表示されることを確認します。
3. `/commands` を実行し、ガイドが `page: 1/4` から表示されることを確認します。
   左右のボタンで全 4 ページを表示し、最初のページと最後のページを行き来できることも確認します。
   各コマンドの詳細とページ番号を確認し、ボタンを素早く押しても表示の整合性が保たれることを確かめます。
   180 秒間ボタンを操作せずに待ち、ページ切り替えが応答しなくなることを確認します。
   `/commands` を再実行すると、新しいガイドを開けることも確認してください。
4. `/ping` を実行し、応答にミリ秒単位の遅延が含まれることを確認します。
5. `/roll maximum:2` と `/roll maximum:1000` を実行し、結果が埋め込みメッセージで表示され、
   それぞれ 1 以上、指定した最大値以下であることを確認します。
6. コマンドの入力画面で `maximum` が必須になっており、2 未満または 1000 を超える値を受け付けないことを確認します。
7. それまでのクールダウンが終わるのを待ちます。
   `/commands`、`/help`、`/ping` をそれぞれ 5 秒以内に 2 回、`/roll` を 10 秒以内に 4 回実行し、
   各コマンドの回数制限を超えると、自分だけに見えるエラーが返ることを確認します。
8. Discord の言語設定を日本語にして、各コマンドをもう一度実行します。
   コマンドの説明、`maximum` の説明、ガイド全 4 ページのタイトルと説明文、
   ヘルプとサイコロの埋め込みメッセージのタイトル、Ping の応答、クールダウンのメッセージを確認します。
9. `!help` を送信し、このプレフィックスコマンドに Bot が応答しないことを確認します。
10. Bot を起動したまま、システムチャンネルと歓迎メッセージ用の権限を設定したテストサーバーへ招待し、
    そのチャンネルに歓迎の埋め込みメッセージが 1 件だけ届くことを確認します。
    サーバーの優先言語が日本語の場合と、それ以外の場合を試し、
    タイトルと説明文がそれぞれ日本語と英語になることを確認します。
11. システムチャンネルがないテストサーバーと、Bot がシステムチャンネルに送信できないテストサーバーでも確認します。
    参加時に歓迎メッセージが送信されず、権限エラーは警告としてログに記録されることを確認します。
    その後もスラッシュコマンドへの応答が続くことを確認してください。

拡張機能を追加した場合は、Bot を再起動し、`src/mybot.py` を編集せずにコマンドや
イベントリスナーが登録されることを確認してください。
名前が `_` で始まるヘルパーモジュールが拡張機能として読み込まれないことも確認します。
イベントリスナーを追加した場合は、リスナー数を確認し、対応するイベントを発生させてください。
コマンドの同期が運用中の環境に影響しないよう、確認にはテスト用の Bot とサーバーを使ってください。

## 日本語対応とエラー処理

Discord の言語設定が日本語のユーザーには、コマンドと引数の説明、
コマンドガイド各ページのタイトルと説明文、
ヘルプとサイコロの埋め込みメッセージのタイトル、Ping の応答、エラーメッセージを日本語で表示します。
それ以外の言語設定では英語を使い、日本語訳がないメッセージも元の英語で表示します。
コマンド名は、どちらの言語でも `/commands`、`/help`、`/ping`、`/roll` のままです。
`/commands` のガイドは、最初に実行したユーザーの言語設定をページ切り替え中も使います。
別のユーザーがボタンを操作しても、表示言語は変わりません。

歓迎の埋め込みメッセージは、Bot がサーバーに参加したときにシステムチャンネルへ送信し、
そのチャンネルで閲覧できます。タイトルと説明文は、`guild.preferred_locale` が日本語（`ja`）なら日本語、
それ以外なら英語になります。Discord では、この値はコミュニティサーバーの優先言語を表し、
デフォルトは `en-US` です。
詳しくは [Guild の構造に関するドキュメント](https://docs.discord.com/developers/resources/guild#guild-object-guild-structure) を参照してください。
歓迎メッセージの権限エラーは警告として、それ以外の HTTP 送信エラーはトレースバック付きでログに記録します。
これらのエラーが起きても、Bot はコマンドへの応答を続けます。

通常のコマンドの応答は、チャンネル内で表示します。
Ping の測定中に `OverflowError` または `ValueError` が発生した場合も、
失敗を知らせるメッセージをチャンネル内で表示します。遅延が `NaN` の場合もこれに含まれます。
スラッシュコマンド共通のエラーハンドラーは、コマンドを実行したユーザーにだけエラーを表示します。
すでにインタラクションへ応答済みの場合は、フォローアップメッセージを使います。
予期しないコマンドエラーは、トレースバック付きでコンソールに記録します。

エラーハンドラーには、権限不足とクールダウン用の専用メッセージがあり、
予期しないエラーには汎用メッセージを使います。
現在、各コマンドに独自の権限チェックは設定していません。
`/commands`、`/help`、`/ping` はそれぞれ、ユーザーごとに 5 秒間に 1 回まで実行できます。
`/roll` は、ユーザーごとに 10 秒間に 3 回まで実行できます。
クールダウンはコマンドごとに独立しています。
