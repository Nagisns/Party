## 開発環境

プロジェクトが要求する Python の最低バージョンは 3.15 です。
[`.python-version`](../../.python-version) では、ローカル開発用に Python 3.15.2 を指定しています。
uv をインストールした環境で、ロックファイルに従って実行用・開発用の依存パッケージをインストールします。

```bash
uv sync --locked
```

## コマンドの追加

コマンドは `src/cogs/` 内の Cog 拡張機能として管理しています。
起動時に `cogs` の直下にあるモジュールとパッケージを検出し、名前のアルファベット順で読み込みます。
名前が `_` で始まるものは除外するため、拡張機能として読み込ませたくないヘルパーモジュールには
この接頭辞を付けてください。

コマンドを追加するには、`src/cogs/example.py` などのモジュールを作成し、
Cog とコマンドを定義します。さらに、`await bot.add_cog(...)` を呼び出す
`async def setup(bot)` をエントリーポイントとして用意してください。
Bot を再起動すると、新しい拡張機能を検出してコマンドを同期します。
`src/mybot.py` を変更する必要はありません。

検出される拡張機能には、すべて `setup` エントリーポイントが必要です。
拡張機能の読み込みに失敗した場合、コマンドを同期する前に起動処理が停止します。

コマンドガイドのページは、`src/cogs/commands.py` の `GuidePage`（`IntEnum`）で定義しています。
`HOME` は 0、それ以降は `auto()` による連番です。ページ切り替えの範囲は
`GuidePage.HOME.value` と `len(GuidePage)` から求め、表示の分岐には列挙型の名前を使います。
ページを追加するときは、列挙型、表示の分岐、目次、対応する日本語の翻訳キーを更新してください。
現在は目次と投票の詳細を含む全 5 ページです。

## イベントリスナーの追加

イベントリスナーは `src/events/` 内の Cog 拡張機能として管理しています。
各リスナーに `commands.Cog.listener()` を付け、`await bot.add_cog(...)` で Cog を登録する
`async def setup(bot)` エントリーポイントを用意してください。
Cog 名には重複しない名前を使ってください。また、`bot.py` からイベント処理を移す場合は、
両方の処理が実行されないよう、元のハンドラーを削除してください。

起動時には、コマンドの拡張機能、イベントの拡張機能の順に読み込みます。
各ディレクトリ直下のモジュールとパッケージは名前のアルファベット順で読み込み、
名前が `_` で始まるものは除外します。
新しいイベントの拡張機能を検出するには Bot を再起動してください。
`src/mybot.py` の変更は不要です。イベントリスナーは Cog の追加時に登録されるため、
`tree.sync()` は必要ありません。

## 起動処理とエラー処理

起動時には、`src/cogs/` からコマンドの拡張機能を、`src/events/` からイベントの拡張機能を
検出して読み込み、日本語の翻訳機能を登録し、グローバルなスラッシュコマンドを同期します。
コンソールには、登録済みの Cog イベントリスナーの総数、同期したコマンド数、
ログインした Bot が表示されます。同じイベントに複数のリスナーが登録されている場合も、
それぞれを個別に数えます。
イベントリスナー数と同期したコマンド数は、`INFO` レベルのログとして出力します。
ready イベントもモジュールのロガーを使い、`Logged in as ...`、`Servers:`、`Users:`、
`Gateway latency:` を同じレベルで記録します。遅延が有限値の場合はミリ秒単位・小数点以下 2 桁で、
それ以外は `unavailable` と表示します。これらのログは再接続後に再び出力されることがあります。

`Users:` は、取得できた `guild.member_count` の合計です。Bot を含み、複数のサーバーに所属する
同じメンバーはサーバーごとに数えます。人数が `None` のサーバーは合計に含めません。
異なるユーザーの実人数を示す値ではなく、メンバーのインテントが無効な場合、
キャッシュ上の人数が最新に保たれる保証もありません。
詳しくは [`Guild.member_count`](https://discordpy.readthedocs.io/en/stable/api.html#discord.Guild.member_count) を参照してください。

歓迎メッセージの権限エラーは警告として、それ以外の HTTP 送信エラーはトレースバック付きでログに記録します。
これらのエラーが起きても、Bot はコマンドへの応答を続けます。

`src/error_handler.py` に `ErrorHandler` を定義しています。
`src/bot.py` でインスタンスを作成し、起動前にその `on_app_command_error` メソッドを
`bot.tree.error()` に登録します。
スラッシュコマンド共通のエラーハンドラーは、コマンドを実行したユーザーにだけエラーを表示します。
すでにインタラクションへ応答済みの場合は、フォローアップメッセージを使います。
予期しないコマンドエラーは、トレースバック付きでコンソールに記録します。
これらのエラーメッセージの送信時に発生した HTTP エラーも、トレースバック付きでログに記録します。

`CommandsView.on_error()` は、ガイドのボタン処理やインタラクションのチェックで発生したエラーを扱います。
元の例外をログに記録し、ボタンを押したユーザーの言語で通知文を作成して、
`ErrorHandler.send_error_message()` を呼び出します。この共通処理が初回の応答、
`defer()` 後のフォローアップ、通知送信時の HTTP エラーを扱います。
タイムアウト時の更新には個別の処理を残しており、メッセージが削除済みなら終了し、
それ以外の HTTP エラーはログに記録します。

ページ切り替えでは、移動先の計算、埋め込みメッセージの生成、更新の送信、ページ番号の確定まで
ロックを保持します。`create_embed(page)` は指定したページの表示を生成し、現在のページ番号を変更しません。
更新に失敗した場合は、現在のページ番号を保持します。

エラーハンドラーには、権限不足とクールダウン用の専用メッセージがあり、
予期しないエラーには汎用メッセージを使います。
現在、各コマンドに独自の権限チェックは設定していません。

## テスト

このプレリリースには自動テストスイートが含まれていません。
セットアップ後は、次の手順で手動確認してください。

1. Bot を起動し、コンソールに登録済みのイベントリスナー数と同期したコマンド数を示す
   `INFO` ログと、ログインした Bot、サーバー数、取得できたメンバー数の合計、
   Gateway 遅延または `unavailable` が表示されることを確認します。
2. `/help` を実行し、埋め込みメッセージに `/commands`、`/help`、`/ping`、`/roll`、`/poll` と各説明が表示されることを確認します。
3. `/commands` を実行し、ガイドが `page: 1/5` から表示されることを確認します。
   左右のボタンで全 5 ページを表示し、最初のページと最後のページを行き来できることも確認します。
   各コマンドの詳細とページ番号を確認し、ボタンを素早く押しても表示の整合性が保たれることを確かめます。
   180 秒間ボタンを操作せずに待ち、左右のボタンが無効になり、`/commands` の再実行を案内する
   有効期限切れの通知が表示されることを確認します。
   `/commands` を再実行すると、新しいガイドを開けることも確認してください。
4. `/ping` を実行し、応答にミリ秒単位の遅延が含まれることを確認します。
5. `/roll maximum:2` と `/roll maximum:1000` を実行し、結果が埋め込みメッセージで表示され、
   それぞれ 1 以上、指定した最大値以下であることを確認します。
6. コマンドの入力画面で `maximum` が必須になっており、2 未満または 1000 を超える値を受け付けないことを確認します。
7. それまでのクールダウンが終わるのを待ちます。
   `/commands`、`/help`、`/ping` をそれぞれ 5 秒以内に 2 回、`/roll` を 10 秒以内に 4 回、`/poll` を 10 秒以内に 2 回実行し、
   各コマンドの回数制限を超えると、自分だけに見えるエラーが返ることを確認します。
8. Discord の言語設定を日本語にして、各コマンドをもう一度実行します。
   コマンドの説明、`maximum` の説明、ガイド全 5 ページのタイトルと説明文、
   ヘルプとサイコロの埋め込みメッセージのタイトル、Ping の応答、投票コマンドと 5 つの引数の説明、
   クールダウンのメッセージを確認します。
   ガイドがタイムアウトするまで待ち、有効期限切れの通知も日本語で表示されることを確認します。
9. `!help` を送信し、このプレフィックスコマンドに Bot が応答しないことを確認します。
10. Bot を起動したまま、システムチャンネルと歓迎メッセージ用の権限を設定したテストサーバーへ招待し、
    そのチャンネルに歓迎の埋め込みメッセージが 1 件だけ届くことを確認します。
    サーバーの優先言語が日本語の場合と、それ以外の場合を試し、
    タイトルと説明文がそれぞれ日本語と英語になることを確認します。
11. システムチャンネルがないテストサーバーと、Bot がシステムチャンネルに送信できないテストサーバーでも確認します。
    参加時に歓迎メッセージが送信されず、権限エラーは警告としてログに記録されることを確認します。
    その後もスラッシュコマンドへの応答が続くことを確認してください。
12. `question`、`option1`、`option2` だけを指定して投票を作成し、選択肢が 2 つ、受付期間が 24 時間で、
    選択肢を 1 つだけ選んで投票できることを確認します。`option3` を追加した場合と、
    `hour:1`・`hour:240` を指定した場合も試し、3 つ目の選択肢と終了時刻を確認してください。
    質問と選択肢は入力した内容のまま表示されることを確認します。
13. 投票の入力範囲を確認します。`question` は 1〜300 文字、各選択肢は 1〜55 文字、
    `hour` は 1〜240 の整数です。質問と最初の 2 つの選択肢が必須で、`option3` と `hour` は省略でき、
    範囲外の値を入力画面が受け付けないことを確認してください。

### ページ更新失敗時の確認

インタラクションをモックに置き換えた独立したテスト用コードで確認します。

- `interaction.response.defer()` は成功させ、`interaction.edit_original_response()` が
  1 回だけ `discord.HTTPException` を送出するようにします。左右それぞれの操作で、
  例外発生後も `view.page` が変わらないことを確認してください。次の更新を成功させ、
  最後に成功した状態から 1 ページ移動することと、先頭・末尾の循環を確認します。
- ボタンのコールバックを直接呼ぶ場合は、その例外を明示的に `view.on_error()` へ渡してください。
  通常は discord.py がこの呼び出しを行います。例外がログに残り、ボタンを押したユーザーの言語で、
  本人にだけ見えるフォローアップ通知が送られることを確認します。初回応答前のケースでは、
  共通処理が `interaction.response.send_message()` を使うことも確認してください。
- 通知送信自体の HTTP エラーがログに記録されることも確認します。
  また、1 件目のページ更新を待機させて 2 件目を開始し、2 件目がロックを待ち、
  最後に更新が成功したページ番号を基準に処理することを確認してください。

拡張機能を追加した場合は、Bot を再起動し、`src/mybot.py` を編集せずにコマンドや
イベントリスナーが登録されることを確認してください。
名前が `_` で始まるヘルパーモジュールが拡張機能として読み込まれないことも確認します。
イベントリスナーを追加した場合は、リスナー数を確認し、対応するイベントを発生させてください。
コマンドの同期が運用中の環境に影響しないよう、確認にはテスト用の Bot とサーバーを使ってください。
